# 视频循环播放与初始化看板入口设计

## 目标

完成两项独立且小范围的界面优化：

1. 所有视频预览在播放结束后自动从头继续，而不是停在末尾。
2. 用户登录进入评测初始化界面后，可以直接从初始化卡片打开看板。

本次明确不实现“返回上一张”或历史重新评测，不新增历史结果编辑能力。

## 范围

视频循环覆盖所有使用共享视频播放控制器的界面：

- 评测主界面的视频 A/B 预览。
- 评测高清预览中的视频 A/B 预览。
- 看板高清预览中的视频预览。

初始化入口只修改评测页的初始化卡片。现有顶部导航栏和其他页面导航保持不变。

## 视频循环架构

循环行为由 `static/video_media.js` 中的 `VideoPlaybackGroup` 统一管理，不在评测模板和看板模板中分别复制结束事件逻辑，也不单纯依赖每个 `<video>` 元素的原生 `loop` 属性。

每个加入播放组的视频新增 `ended` 监听器：

- 同步模式开启时，组内任一视频播放结束，所有组内视频一起回到 0 秒并继续播放。这样即使候选视频时长不同，也不会在循环边界各自重新开始而失去 A/B 同步。
- 同步模式关闭时，只让结束的那个视频回到 0 秒并继续播放，其他视频的播放位置与暂停状态不受影响。
- 循环触发使用播放控制器现有的传播保护，避免 `play`、`pause` 和时间同步事件递归触发。
- 如果浏览器拒绝继续播放的 Promise，控制器吞掉预期的播放拒绝，让视频停留在循环起点，用户仍可通过现有播放按钮恢复，不产生未处理异常。

`remove()` 与 `destroy()` 必须移除新增的 `ended` 监听器。现有暂停、清空媒体源和播放器销毁语义保持不变。

## 初始化界面入口

评测初始化卡片的主操作区改为并列的两个入口：

- 主按钮“进入评测”继续调用现有 `startTest()`，其校验与任务初始化行为不变。
- 次按钮“进入看板”以新标签页打开 `/dashboard`，并设置 `rel="noopener"`。

新标签页打开看板可保留当前初始化界面中已经选择的任务类型、模型、场景和视频评测维度。入口使用链接语义，不触发 `startTest()`，也不要求初始化表单已经填写完整。

现有视频操作提示增加“播放结束后自动循环”的说明。图片任务提示不变。

## 数据与接口

本次不修改：

- FastAPI 路由或请求/响应结构。
- SQLite 表结构或已有数据。
- 任务领取、提交、跳过和进度统计流程。
- 评测结果、个人历史与看板统计语义。
- 视频同步按钮、拖动进度、暂停后画面对照和播放器销毁流程。

## 错误处理

- 循环重播沿用 `VideoPlaybackGroup.play()` 对媒体播放 Promise 拒绝的容错行为。
- 已销毁或已移除的媒体没有 `ended` 监听器，结束事件不能重新激活旧播放器。
- 初始化看板链接使用普通浏览器导航；看板自身继续执行现有登录校验与加载错误处理。

## 测试策略

### 共享视频控制器

扩展 Node 运行时测试，验证：

- 同步模式下任一视频结束会让组内全部视频回到 0 秒并继续播放。
- 非同步模式下仅结束的视频循环，其他视频不被重置或播放。
- `remove()` 后对应媒体不再响应 `ended`。
- `destroy()` 后所有 `ended` 监听器被清理，现有媒体源清理断言继续通过。

### 模板契约

增加评测页契约测试，验证：

- 初始化卡片存在指向 `/dashboard` 的“进入看板”链接。
- 链接使用 `_blank` 与 `noopener`。
- “进入评测”按钮仍调用 `startTest()`。
- 视频任务提示明确自动循环。

看板与评测视频界面继续通过共享 `VideoPlaybackGroup` 获得循环行为，不为每个模板重复结束事件实现。

## 验收标准

- 评测主界面、评测高清预览和看板高清预览中的视频都能自动循环。
- 同步模式循环时 A/B 一起从头播放，非同步模式互不干扰。
- 初始化卡片可以在新标签页打开看板，当前初始化页面状态不丢失。
- 图片评测、视频评分、任务提交、看板数据和数据库均无行为变化。
- 聚焦测试和完整测试套件全部通过。
