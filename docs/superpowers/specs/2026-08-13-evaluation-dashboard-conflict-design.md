# 评测与看板冲突可靠性优化设计

## 背景与目标

本次优化覆盖评测高清预览、视频评测维度、看板明细排序以及统计可靠性。目标是：

1. 让评测界面的高清预览与看板高清预览一样填满浏览器可用视口。
2. 为 T2V 和 TI2V 增加“结构合理性”评测维度，并贯通存储、看板、历史与导出。
3. 让看板明细按完整筛选结果排序后再分页，支持文件名、评测员、评测时间和冲突提示排序。
4. 识别同一样例、同一维度中不同评测员给出的完全相反胜负评价，在明细中标红提示。
5. 为每个维度展示冲突样例数/总样例数，帮助判断结果可靠性。
6. 提供“去除冲突项”统计开关，按维度排除冲突样例并立即刷新全部统计视图。

## 已批准方案

采用“后端统一计算冲突、前端完成明细全量排序”的增量方案。

后端在查询时根据原始评测记录构建共享冲突索引，总览、场景统计、评测员统计、排行榜和明细复用同一冲突定义。冲突状态不写入数据库，历史数据无需回填即可得到正确结果。

明细接口继续一次返回当前模型对和场景的全部记录。浏览器按照“筛选完整数据 → 排序完整数据 → 分页”的顺序处理，避免只对当前页排序。

不采用前后端分别计算冲突的方案，以免明细标红与统计数字产生口径漂移；不新增冲突表或持久化字段，以免每次提交、覆盖和迁移评测记录时维护派生状态。

## 冲突定义

### 样例与评测员身份

一个样例由以下字段共同确定：

```text
task_type + canonical(v_a, v_b) + scene + filename
```

因此，不同任务类型、不同模型对或不同场景中的同名文件互不影响。

评测员身份优先使用 `user_id`。兼容没有 `user_id` 的历史记录时，回退到 `worker`。两类值使用不同命名空间，避免数字用户名与用户 ID 意外相等。

### 判定规则

对每个样例的每个维度，分别收集选择 `v_a` 和选择 `v_b` 的评测员身份集合。仅当存在两个不同评测员，其中一人选择 `v_a`、另一人选择 `v_b` 时，该样例的该维度存在冲突。

以下情况不构成冲突：

- `tie_good` 与任意评价并存。
- `tie_bad` 与任意评价并存。
- 坏例标签或坏例类别不同。
- 某一侧评价为空。
- 只有一个评测员，即使该评测员因历史异常留下相反的重复记录。

如果同一评测员的重复记录之外还存在另一名评测员提供相反胜负评价，仍按“存在两个不同身份给出相反胜负”判定冲突。

### 冲突索引

看板服务对当前查询范围的原始非跳过记录建立冲突索引：

```text
sample_key -> conflicting_dimension_keys
```

维度顺序遵循当前任务类型的 `dashboard_dims` 配置。明细中同一样例的所有评测记录获得相同的冲突维度列表。

## 统计口径

### 冲突可靠性指标

Pair 总览和场景统计中的每个活跃维度增加：

- `conflict_sample_count`：该维度发生冲突的唯一样例数。
- `sample_count`：该维度至少有一条非空评价的唯一样例数。

冲突比例显示为 `conflict_sample_count / sample_count`。分母按样例去重，不按评测记录行计数；平局评价可以让样例进入 `sample_count`，但不会让它进入 `conflict_sample_count`。

现有 `total`、A 胜、一样差、一样好和 B 胜继续按评测记录行计算，以保持已有胜负统计语义。由于同一个维度可能有多名评测员，`total` 可以大于 `sample_count`。

### 去除冲突项

统计筛选栏新增 `exclude_conflicts` 布尔选项，默认关闭。关闭时，原有统计结果保持不变。

开启后采用逐维度排除：

- 某样例在维度 X 冲突，则该样例的所有维度 X 评测记录不参与维度 X 的胜负统计。
- 同一样例在维度 Y 不冲突，则仍参与维度 Y 的统计。
- 不因任一维度冲突而整条删除样例。

`conflict_sample_count` 与 `sample_count` 始终根据未过滤的完整原始数据计算。开启排除后仍显示原始的冲突比例，例如 `3/20`；胜负条形图、数量、百分比和压制比则使用过滤后的记录。这样用户既能看到过滤后的结论，也能看到导致过滤的可靠性信息。

Pair 和场景级总记录数保持原始记录口径，因为逐维度排除无法产生一个适用于所有维度的公共过滤后总数。每个维度自己的 `total` 是其胜负统计的实际分母。

### 统计视图覆盖范围

“去除冲突项”开关统一作用于：

- Pair 总览。
- 场景统计。
- 评测员统计。
- 模型排行榜。

评测员统计和排行榜在计算目标维度前，使用同一全局冲突索引排除该维度的冲突样例记录。明细始终展示全部原始记录及冲突提示，不受开关影响。

冲突比例明确展示在 Pair 和场景的维度统计中。评测员统计与排行榜必须服从相同过滤口径，但不新增重复的冲突比例展示。

## 后端接口与服务

### 共享冲突分析

`app_core/dashboard_service.py` 增加小型、无副作用的冲突分析单元，负责：

- 生成稳定的评测员身份。
- 生成样例键。
- 按配置维度构建冲突索引。
- 判断一条记录是否属于指定维度的冲突样例。
- 为明细记录生成配置顺序的冲突维度列表。

`dimension_stats` 接收冲突索引和 `exclude_conflicts`，先确定该维度的完整非空记录，再按需移除冲突样例记录。冲突可靠性指标始终基于过滤前的完整记录计算。

### API 参数

以下接口增加可选布尔查询参数 `exclude_conflicts=false`：

```text
GET /api/dashboard_overview
GET /api/worker_stats
GET /api/ranking
```

未提供参数时行为与现有版本相同。FastAPI 负责布尔解析，服务函数显式接收并传递该值。

`GET /api/detail_results` 不增加过滤参数，继续返回完整记录。每行新增：

```json
{
  "has_conflict": true,
  "conflict_dimensions": ["overall", "structure_reasonableness"]
}
```

`conflict_dimensions` 使用任务配置顺序，前端通过 `dashboard_dims` 将键转换为中文名称。

### 请求范围

冲突分析只处理当前接口已经读取的任务类型、模型对和可选场景范围，不扫描媒体文件，不修改原始记录。排行榜覆盖多个模型对时，样例键包含规范化模型对，避免不同对战之间互相造成冲突。

## T2V/TI2V 结构合理性维度

新增字段：

| Key | Label |
|---|---|
| `structure_reasonableness` | 结构合理性 |

T2V 使用以下精确顺序：

1. 整体。
2. 文本一致性。
3. 结构合理性。
4. 运动合理性。
5. 动态度。
6. 物理规律与常识。
7. 画面细节与美感。

TI2V 使用全部 T2V 维度，并在最后保留“图像一致性”。

新维度沿用现有配置驱动的视频评测机制，并贯通：

- `TASK_CONFIGS`、`DIM_LABELS` 和视频评分字段集合。
- `VoteSubmit` 请求 schema。
- `results_log` 的幂等可空列迁移。
- 视频投票提交和跳过记录 SQL。
- 评测页所选维度、投票状态与提交 payload。
- 看板活跃维度、明细和排行榜。
- 个人历史记录。
- 导出选项、筛选、工作簿列和值。
- README 中的维度说明。

旧视频结果的新列为 `NULL`，不会被误认为平局或缺失投票。已有视频评测范围不会被静默加入新维度；用户选择包含“结构合理性”的严格超集时，继续使用现有的确认后清空旧结果并重新评测规则。

## 评测高清预览布局

当前评测页 `.lightbox-dialog` 使用 `width: min(1700px, 100%)` 和 `height: min(92vh, 1020px)`，在大屏上必然留下明显空白；看板 stage 则填满 overlay 的可用视口。这是两者视觉不一致的根因。

评测页改用与看板一致的视口填充约束：

- overlay 安全边距统一为 12px。
- 预览主体宽度为 `100%`。
- 高度先提供 `calc(100vh - 24px)` 回退，再使用 `calc(100dvh - 24px)`。
- 移除 1700px 宽度、1020px 高度和 92vh 封顶。
- 保留现有圆角、标题、Prompt、工具栏、媒体网格和窄屏断点。

本次只修复 stage 尺寸，不修改 `PreviewController`、缩放范围、深浅背景、同步、视频播放、按住比较、放大镜或快捷键行为。

## 看板明细排序与冲突提示

### 可排序表头

明细表增加“冲突提示”列。以下列名后放置独立排序按钮：

- 文件名。
- 冲突提示。
- 评测员。
- 时间。

排序按钮展示当前方向，并用 `aria-sort` 和可读标签表达当前选中列与方向。未选择排序列时保留接口现有默认顺序。

首次点击默认方向：

- 文件名：升序。
- 评测员：升序。
- 时间：最新优先。
- 冲突提示：存在冲突优先。

再次点击同一列反转方向。点击另一列时切换到该列的首次默认方向。每次改变排序都回到第一页。

字符串排序使用当前页面一致的 `localeCompare` 语义。时间使用可比较时间值；无效或缺失时间稳定落在末尾。所有排序保留原始索引作为最终稳定次键，避免相同值在重复渲染时跳动。

### 冲突排序

冲突列以冲突状态为主键、文件名为次键：

- 第一次点击：存在冲突的样例在前。
- 第二次点击：无冲突的样例在前。
- 每个分组内部按文件名升序。
- 同一文件的多名评测员记录保持相邻，再以评测员和时间提供确定性顺序。

### 完整排序与分页

`renderDetailTable()` 的数据处理顺序固定为：

1. 对 `state.detailRows` 应用评测员、文件名和判定筛选。
2. 对全部筛选结果应用当前排序。
3. 更新匹配条数。
4. 对已排序的完整结果调用分页函数。
5. 只为当前页创建行和缩略图节点。

排序绝不能应用于 `pagination.items`。该顺序保持现有 50 条/页、缩略图懒加载和关闭清理优化。

### 冲突列展示

`has_conflict=true` 时显示红色“存在冲突”，并通过 `title` 或等价可访问说明列出中文冲突维度。`has_conflict=false` 时显示普通颜色“无”。同一样例的所有评测记录显示一致状态，便于同时检查不同评测员原始评价。

空状态表格的跨列数随新增列从 7 调整为 8。

## 统计开关与刷新

在“任务控制与筛选”卡片增加“去除冲突项”复选框，默认不选中。`change` 事件立即发起刷新，不要求用户再点击“刷新”。

前端状态保存当前布尔值，并把它作为查询参数传给总览、评测员统计和排行榜：

- 总览始终刷新。
- 排行榜当前已打开时同步刷新。
- 评测员统计弹窗当前已打开时使用保存的模型对和场景同步刷新。
- 明细弹窗和坏例弹窗不重新请求，也不隐藏记录。

总览、排行榜和评测员统计各自沿用或补充请求序号保护。用户连续切换开关、切换任务类型或关闭弹窗时，只有最后一次仍有效的响应可以更新界面。

Pair 摘要框和场景维度单元格增加“冲突样例 X/Y（Z%）”。`Y=0` 时显示 `0/0（0.0%）`，不执行除零计算。开启去冲突后，该可靠性行保持不变，胜负条、图例和压制比随过滤后数据刷新。

## 兼容性与边界处理

- 数据库迁移采用现有 `ensure_column` 幂等模式，重复启动安全。
- T2I/TI2I 的配置、投票字段和界面维度保持不变。
- 一名评测员的范围内冲突数必为 0，除非范围内还存在另一名不同身份评测员的相反评价。
- 维度全部为空时保持非活跃，不显示对应统计卡。
- `sample_count=0` 时冲突比例为 0，不产生 `NaN` 或除零异常。
- 缺失 `user_id`、排序字段或冲突字段的历史/兼容数据使用安全回退，不导致页面崩溃。
- 冲突分析只读取结果，不修正、删除或覆盖任何评测记录。
- 未传 `exclude_conflicts` 时 API 和页面统计保持当前结果。
- 明细缩略图、高清原始媒体加载、视频首帧和坏例逻辑不因排序或冲突计算改变。

## 测试策略

所有生产行为改动遵循红—绿—重构循环，每项先增加能够按预期失败的测试。

### 冲突服务测试

覆盖：

- 不同评测员分别选择 A/B 时判定冲突。
- 同一评测员的相反重复记录不构成冲突。
- `tie_good`、`tie_bad`、坏例和空值不构成冲突。
- 不同任务类型、模型对、场景或文件名不互相冲突。
- `user_id` 优先和历史 `worker` 回退。
- 冲突只排除目标维度，其他维度保留。
- `conflict_sample_count/sample_count` 按唯一样例计数，而胜负 `total` 按记录行计数。
- 开关关闭时现有四路胜负统计完全不变。
- Pair、场景、评测员统计和排行榜共享过滤结果。
- 明细行获得配置顺序的 `has_conflict` 与 `conflict_dimensions`。

### 新视频维度测试

覆盖：

- T2V/TI2V 配置顺序和中文标签。
- 数据库新列的首次创建与重复初始化。
- 维度选择规范化、投票提交、未选择时强制 `NULL`、跳过和严格超集重评。
- 看板活跃维度、明细、个人历史、排行榜和导出包含新字段。
- T2I/TI2I schema 和行为不回归。

### 明细前端测试

通过现有 Node 函数探针覆盖：

- 文件名、评测员、时间和冲突四种首次默认方向。
- 再次点击反转方向，切换列恢复该列默认方向。
- 冲突状态主排序、文件名次排序以及同文件记录相邻。
- 相同值的稳定顺序与缺失值回退。
- 排序发生在分页之前，跨页数据排序正确。
- 切换排序回到第一页。
- 冲突红字、无冲突文字、中文维度提示和 8 列空状态。

### 预览与统计前端测试

覆盖：

- 真实浏览器几何探针验证评测高清主体宽高等于 overlay 扣除 12px 安全边距后的可用区域。

- 查询参数正确、明细不受开关影响、迟到响应不覆盖最新状态。
- Pair/场景显示冲突数量、分母和比例，零分母输出稳定。

- 评测高清预览在桌面和窄屏都填满 overlay 可用空间，行为与看板预览一致。
- T2V/TI2V 可以选择、提交、存储、展示、统计并导出“结构合理性”。
