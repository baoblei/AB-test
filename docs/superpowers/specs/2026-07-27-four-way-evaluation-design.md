# 四档评测、TI2I 三图布局与结果统计设计

## 背景

当前评测界面只支持“A 更好 / 平局 / B 更好”三种选择，无法区分两个模型“都差”与“都好”。TI2I 评测把参考图放在候选图之前，不利于左右对照；结果看板也只显示胜、平、负三段。

本次采用最小兼容扩展：A/B 胜仍保存真实模型名，两类平局分别保存为 `tie_bad` 和 `tie_good`，不修改数据库表结构。现有评测数据会被清空，因此不保留普通 `tie` 的展示或迁移逻辑。

## 目标行为

### 评测图片布局

- TI2I 主评测区固定按“候选图 A / 参考图 / 候选图 B”从左到右排列。
- TI2I 高清预览使用相同顺序，图片 pane 与按住覆盖比较关系随顺序一起更新。
- T2I 继续显示“候选图 A / 候选图 B”，其他预览能力保持不变。

### 四档人工评测

- T2I、TI2I 的所有维度统一提供“A 好 / 一样差 / 一样好 / B 好”四个选项。
- 整体快速评测使用同样四个选项。
- 完整多维度评测新增必填“整体”行，不再根据细分维度自动推导整体结果。
- 键盘快捷键 `1 / 2 / 3 / 4` 依次选择“A 好 / 一样差 / 一样好 / B 好”，仍作用于第一个未选择维度。
- 请求失败后恢复选项时，A/B 选择按当前随机左右位置重新映射；`tie_bad` 和 `tie_good` 不需要映射。

### 结果存储与校验

- 前端提交值限定为 `left`、`tie_bad`、`tie_good`、`right`。
- 后端把 `left`、`right` 映射为当前任务两侧的真实模型名，把 `tie_bad`、`tie_good` 原样保存。
- 完整评测必须同时提交人工整体结果和任务类型要求的全部细分维度；整体快速评测只要求整体结果。
- 缺失值或未知选择返回业务错误，不能再默认降级为普通 `tie`。
- T2I 不适用的 `fidelity` 保存为 `NULL`；跳过记录的所有结果字段保存为 `NULL`，避免再次写入普通 `tie`。

## 统计与展示

每个维度返回以下计数：

- `v_a_wins`：模型 A 胜。
- `tie_bad_count`：一样差。
- `tie_good_count`：一样好。
- `v_b_wins`：模型 B 胜。
- `tie_count`：`tie_bad_count + tie_good_count`，仅作为合计统计和压制比输入。

看板汇总卡和场景明细的进度条按“A 胜 / 一样差 / 一样好 / B 胜”显示四段、四个百分比与数量。无样本时继续显示空状态。

压制比保持原公式，但将两种平局合并：

- A 压制 = `(A 胜 + tie_count) / (B 胜 + tie_count)`。
- B 压制 = `(B 胜 + tie_count) / (A 胜 + tie_count)`。

排名胜率只把模型 A/B 的胜场计为 wins；两种平局都不计胜场。看板详情、个人记录、结果筛选和 Excel 导出均使用“一样差 / 一样好”两个独立标签，不再生成或展示普通“平局”。结果筛选提供“全部 / A 胜 / 一样差 / 一样好 / B 胜”；导出汇总分别输出两种平局的数量和比例，压制比继续使用二者合计。

## 数据流

1. 前端按当前图片随机左右位置收集四档选择，并把人工整体结果与细分维度一起提交。
2. 任务服务验证每个必填选择，映射左右模型，将四类结果写入现有文本字段。
3. Dashboard 服务按维度聚合四类计数，并额外返回两种平局的合计。
4. 看板用四类计数绘制四段 bar，用合计 `tie_count` 计算压制比。
5. 详情、筛选、个人记录和导出复用相同的结果值与中文标签，避免各页面解释不一致。

## 数据清理

- 在单个事务中清空 `results_log` 和 `pair_tasks`。
- 保留 `users`、`operation_logs`、`app_metadata` 及其他表。
- 不删除或改动 prompt、参考图、模型结果图等文件。
- 清理完成后查询两张表，确认记录数均为 0。

## 错误与边界

- 任一必要维度或整体结果缺失时拒绝提交，任务保持可继续评测。
- 任一选择不在四个允许值中时拒绝提交，不能把拼写错误当作平局。
- 统计总数为 0 时不计算百分比除法，界面显示现有空状态。
- 压制比分母为 0 时沿用当前 `∞` 或 `-` 的展示规则。
- 本次不引入历史 `tie` 兼容分支；清库后新流程不会再写入该值。

## 测试与验收

- UI 测试验证 TI2I 主界面和高清预览均按 A / 参考图 / B 排列，T2I 顺序不变。
- UI 测试验证表头、各维度选项及 `1 / 2 / 3 / 4` 快捷键的四档映射。
- 服务测试覆盖左右模型映射、`tie_bad`/`tie_good` 落库、人工整体必填、未知选择拒绝，以及 T2I 不适用字段和跳过字段为 `NULL`。
- 聚合测试验证四类计数、`tie_count` 合计及压制比输入。
- 看板运行时测试验证汇总卡和场景行都生成四段 bar 与四类图例。
- 详情、个人记录、结果筛选和导出测试验证两类平局分别展示和筛选，导出汇总同时保持合并 tie 的压制比。
- 运行相关专项测试、完整测试、Python 编译、模板 JavaScript 语法检查和 `git diff --check`。
- 清库后直接查询数据库，确认 `results_log=0`、`pair_tasks=0`，并确认用户和操作日志未被清除。

## 非目标

- 不修改数据库表结构。
- 不保留或猜测旧普通 `tie` 的“一样好/一样差”含义。
- 不改变坏例标签体系、图片缩放/同步能力、任务随机左右展示或模型数据目录。
- 不重设计看板中与四档统计无关的区域。
