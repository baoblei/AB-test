# 高清预览完整浅色主题修复设计

## 目标

修复评测界面和看板界面的高清预览主题切换：从深色切换到浅色后，整个高清预览都应变为浅色，不再残留固定深色的外层容器、标题区、间距、工具栏或状态提示。

## 范围

- 覆盖评测页 `templates/index.html` 的高清预览。
- 覆盖看板页 `templates/dashboard.html` 的高清预览。
- 浅色主题作用于遮罩、弹窗、标题与 Prompt、内容区、pane 标题、媒体留白、工具栏、提示文字、边框和加载/错误提示。
- 图片和视频画面本身不做颜色变换。
- 视频播放控件与放大镜等需要保证可读性的浮层可保留半透明对比底色，但不得形成大面积固定深色背景。
- 普通评测区现有的单个图片背景切换行为保持兼容。
- 不修改后端接口、预览缩放/同步状态结构或媒体数据流。

## 根因

两套预览都由预览组中的 `darkBackground` 保存主题状态，但状态只被投射到最内层媒体 pane：

- 评测页仅给 `[data-preview-group-pane]` 切换 `preview-dark`，而 `.lightbox`、`.lightbox-dialog`、`.lightbox-grid`、`.pane` 和 `.pane-head` 仍使用固定深色。
- 看板页仅给 `.dashboard-preview-viewport` 切换 `preview-light`，而 `#image-overlay`、`.dashboard-preview-stage`、网格留白和其他浮层仍使用固定深色。

因此浅色状态虽然已经进入控制器，却没有覆盖完整的高清预览视觉表面。

## 方案选择

采用“根节点主题类 + CSS 变量”的方案：主题切换时，把状态同步到高清预览根节点；根节点通过一组语义化 CSS 变量控制所有子区域的背景、文字、边框和浮层颜色。

不采用逐层切换多个 class 的方案，因为新增或重绘子节点时容易再次漏掉某层。不采用依赖 `:has()` 从按钮状态推导主题的方案，因为按钮不是主题状态源，并会增加浏览器兼容与测试复杂度。

## 主题状态与 DOM

### 评测页

- `PreviewController` 继续作为 `darkBackground` 的唯一状态源。
- `togglePreviewBackground("lightbox")` 除更新现有 pane 外，还在 `#lightbox` 上同步一个浅色主题类。
- 普通评测区 `main` 不把主题扩展到整页，只保持现有 pane 级切换。
- 高清预览重新渲染、关闭再打开时，根节点主题类必须与当前 `lightbox` 预览组状态一致，避免 DOM 重绘后主题分裂。

### 看板页

- `PreviewController` 继续保存 `overlay` 预览组的 `darkBackground`。
- 背景按钮更新状态后，在 `#image-overlay` 上同步浅色主题类。
- 打开新的高清预览仍以深色为默认；关闭时清理浅色主题类，避免下一条记录继承旧状态。
- 动态创建的媒体 pane 依赖根节点继承的 CSS 变量，无需逐个恢复主题类。

## 视觉规则

深色主题保持当前视觉。浅色主题至少满足：

- 遮罩和弹窗主体使用浅色背景。
- 标题、Prompt、pane 标签和辅助文字改为深色文字。
- 内容网格、媒体留白、网格间距和响应式布局留下的空白均显示浅色。
- 工具栏、快捷键帮助、图片信息、加载提示和错误提示使用浅色面板及可读的深色文字。
- 边框、阴影和激活态在浅色背景上保持足够对比。
- 图片和视频不应用滤镜；视频元素的空白背景跟随主题。
- 关闭按钮、播放控件、放大镜和覆盖对比等交互控件在两种主题下均可辨识。

## 测试策略

按 TDD 添加两个最小回归场景：

1. 评测页：执行高清预览背景切换，断言 `#lightbox` 根节点进入浅色主题，且弹窗、pane 标题、媒体留白和工具栏的计算颜色不再是深色。
2. 看板页：执行背景按钮处理，断言 `#image-overlay` 根节点进入浅色主题，且遮罩、舞台、网格留白、媒体视口和工具栏的计算颜色均为浅色系。

每个测试先在当前实现上按预期失败，再添加最小生产代码使其通过。随后验证：

- 深色 → 浅色 → 深色切换可逆。
- 关闭并重新打开看板高清预览时恢复默认深色。
- 评测主预览原有背景切换不受高清根节点主题影响。
- 图片与视频预览、响应式布局和既有前端契约测试不回归。

## 完成标准

- 评测界面和看板界面的高清预览切换到浅色后，所有可见 UI 表面均为浅色主题，不存在大面积固定深色残留。
- 切回深色后恢复现有深色视觉。
- 主题状态在动态渲染、关闭和重新打开过程中符合上述规则。
- 新增回归测试与相关完整测试通过，生产代码改动仅限主题同步和样式覆盖。
